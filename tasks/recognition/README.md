# AI screenshot recognition

## Validated local party reader (2026-09-14; supersedes inference-first party notes below)

Party crops are detected from connected purple card bodies and a coherent 2-column/3-row arrangement, not fixed screen coordinates. Dense body rows exclude protruding portraits; padding is relative to detected card size. Unsupported/incomplete grids are rejected, never replaced with guessed coordinates. `tests/party-layout-adaptive.mjs` checks three independent source pairs across 96 deterministic scale/translation/padding variants, plus missing-card rejection. This is geometry coverage, not proof of OCR accuracy on 96 images. Run `tests/live-party-page.mjs --local` with `--cross` or `--wide`, and `--720p` or `--transform`, for actual 84-field page validation. All fixtures/expected answers stay test-only. OCR additionally separates decorative slot numerals across large whitespace gaps, retries unread crops with bounded contrast/padding variants, and requires observed XY suffix evidence.

`local-party-text.mjs` reads source pixels with the locally hosted Tesseract worker. No external request on party upload. `recognition-text-validation.mjs` compares OCR spelling against the entire official dictionary, never a species' usage set. Nature is read from red-up/blue-down pixels. Species confirmation requires all six observed stats and EVs to uniquely satisfy the existing `calculateStats` equations; alternate OCR readings may be resolved only when the matching values were actually observed, never invented from the DB. Missing/ambiguous observations remain empty. This is arithmetic evidence, not permission to auto-confirm generic image-template rankings.

Only the explicit AI assistance button may invoke the existing bounded recognition API, and fully read local results skip even that request. The fallback model remains the low-cost existing model; the unsuccessful model experiments are not a release upgrade. Browser assets live under `vendor/party-text`, not the retired `vendor/ocr` path.

Release tests: `local-text-validation.mjs`, `local-party-reader.mjs` (also `--cross`, `--720p`, `--cross --erase`), and `live-party-page.mjs --local` (also `--cross`, `--720p`). Both party fixture pairs pass 84/84 actual-page fields at original and 720p JPEG size, with the inference transport blocked and zero calls. Erasing source text/stat evidence must not reproduce an answer from a fixture. `lead-candidate-page.mjs` verifies 24 known-reference slots; it is not unseen-image accuracy. `recognition-reference-labels.mjs` prevents mislabeled screen crops. Inspect saved page screenshots manually before deployment.

OCR draft safety: name selection must only select a species, never fill moves/items/abilities/nature/EVs from usage statistics. `ocr-draft.mjs` also prevents apply from inheriting hidden previous-set fields or treating unread EVs as zero. Keep four move edit positions stable and render moves in a dedicated 2x2 grid on desktop and mobile. Run `node tests/ocr-draft.mjs` and `node tests/ocr-draft-browser.mjs`. These verify state/UI only, NOT actual text recognition accuracy. Actual source-image extraction must separately match the fixture's 24 moves, 6 items, 6 abilities and 36 EV values before release approval.

Scope: browser image preparation, `/recognize` request/response validation, and the AWS recognition Lambda. The browser never receives the OpenAI key. Keep requests to at most four resized images, one model call, a 135 second client timeout (120 second Lambda window plus transfer), and a strict six-slot schema. Run `node tests/recognition.mjs`.

Local-first update: lead uploads use `local-icon-model.mjs` and non-neural masked-colour template matching in a module Worker. The ridge classifier experiment was inferior and is NOT loaded at runtime. Local scores are candidate rankings only, never automatic names. No automatic external inference on lead upload: the separate AI button is explicit opt-in. Party details retain their existing inference path. Run `tests/local-icon-model.mjs` with Playwright/Edge. Evaluation excludes all exact-crop references. The four evaluation screens were used for development comparisons and are not an untouched final test set. Do not enable template/model auto-confirmation until independently calibrated and tested.

Images: `champions-image-catalog.json` records all 316 master names/forms, source URLs, 512px dimensions and hashes. The shared display renderer uses `champions-image-map.json`; recognition uses 235 current names from `champions-icon-map.json`. No PokeAPI image fallback. `sync_champions_display.py` downloads public originals sequentially for the user's explicitly requested personal local use, stopping on 401/403/429; no deployment. Its species-index lookup is for English-name-to-dex image IDs only, not battle data. Run `build_champions_recognition_assets.py` after updating the display catalog, then `tests/champions-images.mjs` and `audit_champions_images.mjs`.

Cost/accuracy policy (2026-09-14): use the low-cost recognition default, not the party-analysis model. Default lead uploads never call external inference. Even after explicit AI opt-in, skip inference if all 12 lead slots have distinct, separated near-exact slot-crop evidence. Never infer names from a whole-screen fixture signature. Reuse identical successful requests within the session; do not retry upstream automatically. A name conflict or low confidence must remain unresolved. Party details still require inference until a separately validated local text reader exists. Do not fill unrecognized fields from popular statistical sets.

Run `node tests/recognition-merge.mjs`, `node tests/recognition-cost-routing.mjs` (Playwright/Edge), and `python tests/recognizer_request_test.py`. The browser routing test uses real fixture pixels and stubbed inference, so it does not certify the new model's recognition accuracy. Full fixture acceptance must be evaluated separately before claiming model accuracy.
