# 포케챔스 기능 벤치마크

## 결론

달콤아 봇은 **파티 추천·상대 선출 추천·스크린샷 인식**에서 이미 차별점이 있다. 포케챔스와 동등한 제품 범위를 만들기 위해서는 그 위에 (1) 전체 도감 탐색, (2) 최신 싱글/더블 통계, (3) 재사용·공유 가능한 세팅, (4) 조건을 빠짐없이 반영하는 계산기라는 네 개의 기반 기능을 추가해야 한다. 단순히 화면만 복제하지 말고, 현재의 “추천으로 결정” 흐름에 각 기능을 연결하는 것이 제품 가치가 더 크다.

## 조사 범위와 근거

2026-09-14 기준 공개 웹을 조사했다. 아래 내용은 로그인하지 않아도 보이는 기능과 공식 데이터 출처 설명에 한정한다.

- [포케챔스 홈](https://pokemon.yodams.com/) — 도감, 샘플, 계산기, 싱글/더블 통계, 배포·소식의 제품 범위.
- [포켓몬 도감](https://pokemon.yodams.com/dex/pokemon) — 종족값, 타입, 특성, 기술 단위 탐색.
- [샘플 작성](https://pokemon.yodams.com/sample/write) — 포켓몬·특성·성격·도구·4기술·노력치로 세팅 작성, 저장·공유.
- [결정력 계산기](https://pokemon.yodams.com/calc/damage), [대전 데미지 계산기](https://pokemon.yodams.com/calc/battle), [내구력 계산기](https://pokemon.yodams.com/calc/bulk), [스피드 계산기](https://pokemon.yodams.com/calc/speed) — 챔피언스 규칙의 계산 범위.
- [싱글 통계](https://pokemon.yodams.com/stats/single), [한카리아스 싱글 상세 예시](https://pokemon.yodams.com/stats/single/garchomp/), [더블 통계](https://pokemon.yodams.com/stats/double) — 사용률, 세팅 분포, 팀메이트와 카운터.
- [데이터·통계 출처](https://pokemon.yodams.com/data-sources.html) — 스프라이트와 카운터 통계의 출처 및 한계.

## 제품 요구사항

### P0 — 파티 커버리지·통계·도감·계산의 신뢰 가능한 기반

1. **파티 커버리지 진단과 보완 후보 (최우선)**
   - 진입 시 달콤아의 현재 6슬롯 파티를 즉시 불러오며, 비어 있는 슬롯은 빈 상태로 유지한다. 별도 저장 파티/JSON을 불러온 경우도 같은 분석 입력으로 쓴다.
   - 화면 상단에 `초기화`와 `파티 불러오기`를 두고, 각 슬롯은 아이콘·이름·선택 세팅을 보여 주며 개별 교체/해제가 가능해야 한다.
   - 현재 6마리의 방어 상성을 18타입별로 `무효 / 1/4 / 1/2 / 1배 / 2배 / 4배`와 각 개수로 집계한다.
   - 상성표는 행=공격 타입, 열=파티원으로 고정한다. 마지막에는 각 타입의 약점 수와 `좋음 / 보통 / 주의 / 위험` 평가를 표시한다. 싱글/더블 전환은 분석 규칙과 추천 가중치에 영향을 주므로 명시적으로 분리한다.
   - ‘공통 약점’, ‘안정적인 받이 부재’, ‘중복 역할’, ‘공격 커버리지 공백’을 서로 구분해 표시한다. 타입만으로 단정할 수 없는 특성·테라·도구·기술은 별도 보정/주의 표시를 둔다.
   - 후보는 단순 점수순이 아니라 **해결하는 약점, 새로 생기는 약점, 파티의 기존 역할과의 충돌, 근거 데이터**를 함께 설명한다.
   - 추천 카드에는 순위, 포켓몬, “완화하는 약점 · 추가 견제 범위 · 역할”, 관련 세팅을 넣고, 세팅을 펼쳐 확인한 뒤 파티에 적용할 수 있게 한다.
   - 후보 선택 시 현재 파티의 빈 슬롯에 임시 적용하여 전/후 상성표와 추천·선출 영향이 즉시 비교되어야 한다.
   - 초기에는 타입 기반의 재현 가능한 규칙을 제공하고, 이후 실제 사용률·팀메이트 통계·사용자 세팅을 가중치로 추가한다. AI 추천은 판정 근거를 숨기지 않는다.

2. **도감 데이터 모델**
   - 폼을 독립 식별자로 둔다.
   - 종족값, 타입, 특성, 사용 가능 기술, 메가/테라 가능 조건을 구조화한다.
   - 검색은 한국어 이름, 영문명, 폼명, 타입으로 동작해야 한다.

3. **통계 수집과 표시**
   - 싱글·더블을 완전히 분리하고, 각 화면에 시즌·집계 기간·갱신 시각·표본·출처를 표시한다.
   - 포켓몬 상세는 사용률, 기술, 도구, 특성, 성격, 노력치, 팀메이트, 카운터를 탭으로 분리한다.
   - 서로 다른 모집단의 수치를 합산하거나 동일한 ‘사용률’로 표현하지 않는다.

4. **상세 계산기**
   - 입력: 공격/방어 세팅, 기술, 레벨, 필드, 날씨, 랭크 변화, 테라스탈, 메가진화, 도구, 특성, 벽, 더블 광역 보정.
   - 출력: 최소~최대 피해, HP 비율, 난수 분포, 확정/난수 n타, 계산에 포함/제외한 조건.
   - 현재의 빠른 대조표는 유지하되, 상세 계산은 별도 탭으로 제공한다.

### P1 — 반복 사용과 탐색성

1. **내 세팅 라이브러리**: 저장, 이름 변경, 태그, 복제, 삭제, JSON 백업/복원, 파티로 삽입.
2. **스피드 티어**: 현재 파티 세팅으로 추월 가능한 티어와 위험한 동속 구간을 시각화.
3. **교차 연결**: 도감·통계·계산기 어디서든 “파티에 추가”, “계산기에 넣기”, “선출 분석에 사용”을 제공.
4. **메타 대시보드**: 싱글/더블 전환, 사용률 변화, 상위 조합, 자주 쓰이는 아이템/기술을 한 화면에서 탐색.

### P2 — 커뮤니티 기능

공유 세팅/파티, 검색, 좋아요, 신고, 작성자 프로필은 별도의 계정·권한·삭제·저작권·악용 대응이 필요하다. 현재의 로그인 없는 정적 앱에 바로 붙이면 운영 위험이 커지므로, P1의 로컬 라이브러리와 JSON 공유를 먼저 완성한 뒤 도입한다.

## 권장 사용자 흐름

`도감/통계에서 포켓몬 탐색 → 검증된 세팅을 내 라이브러리에 저장 → 파티 구성 → 방어·공격 커버리지 진단과 보완 후보 비교 → 상세 계산으로 대면 검증 → 상대 스크린샷 인식 → 선출/순서 추천`

이 흐름은 포케챔스의 탐색·계산 장점을 흡수하면서, 달콤아 봇의 AI 입력과 실제 선출 결정을 중심에 둔다.

## 데이터·법적 가드레일

- 포케챔스는 스프라이트에 PokéAPI와 CDN을 사용하고, 카운터는 Smogon/Showdown 기반임을 공개한다. 특히 더블 카운터도 싱글 BSS 데이터를 표시하며 Switch 랭크와 차이가 날 수 있다고 고지한다. 달콤아도 이 수준 이상으로 출처·시점·포맷·한계를 표시해야 한다.
- 이미지, 통계, 샘플 원본을 수집하거나 재배포하기 전에 각 출처의 이용 조건을 확인한다. 페이지 구성이나 문구를 복사하지 않고, 기능 목표와 독자적인 UI·데이터 모델을 구현한다.
- AI 인식 결과와 추천 점수는 확률적 보조 정보이며 실제 승률·정답으로 단정하지 않는다.

## 구현 순서

1. 파티 방어 상성/공격 커버리지 엔진, 추천 근거 모델, 전·후 비교 UI와 단위 테스트.
2. 도감용 정규화 데이터와 포켓몬 상세 화면.
3. 통계 수집 계약, 싱글/더블 메타 화면, 출처·갱신 시각 표시.
4. 상세 데미지/내구/스피드 계산 엔진과 테스트 벡터.
5. 세팅 라이브러리 및 모든 기능 간 딥링크.
6. 계정 기반 공유·커뮤니티 기능의 별도 설계와 보안 검토.

## 성공 기준

- 현재 6마리를 넣으면 18타입의 방어 분포, 공통 약점, 공격 커버리지 공백, 보완 후보와 각 후보의 근거를 확인하고 전/후를 비교할 수 있다.
- 사용자가 어떤 포켓몬/폼이든 도감에서 찾고, 통계 세팅을 확인해 한 번의 동작으로 파티나 계산기에 넣을 수 있다.
- 계산 결과가 입력 조건·난수·확정타를 재현 가능하게 명시한다.
- 모든 통계에는 모드, 시즌/기간, 갱신 시각, 표본, 출처가 있다.
- 스크린샷 인식 후에도 사람이 후보·세팅을 교정할 수 있으며, 그 교정값이 라이브러리와 계산기에 재사용된다.
